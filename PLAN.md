# План роботи — Quizlet-like app (Vue 3 → Nuxt 4)

Стек: Nuxt 4 (Vue 3, Composition API) · TypeScript · Pinia · Tailwind CSS v4 · Vitest (кроки 1–11 зроблені на Vite + Vue Router)

## Етап 1 — MVP

- [x] **1. Ініціалізація проєкту** — create-vue (TS, Router, Pinia, Vitest, ESLint, Prettier), прибирання демо-коду
- [x] **2. Tailwind CSS + базовий layout** — підключення Tailwind через Vite-плагін, шапка застосунку, контейнер сторінки
- [x] **3. Модель даних і стор** — типи `Card` / `StudySet`, Pinia-стор з CRUD, збереження в `localStorage`, демо-набір, unit-тести
- [x] **4. Маршрути і сторінки** — головна (список наборів), сторінка набору (перегляд карток, кнопки режимів)
- [x] **5. Редактор набору** — створення/редагування: назва, опис, додавання/видалення/перестановка карток, валідація
- [x] **6. Режим Flashcards** — 3D-перевертання картки, навігація ←/→, перемішування, клавіатурні скорочення, прогрес

## Етап 2 — Режими навчання

- [x] **7. Режим Learn** — вибір з 4 варіантів + письмова відповідь, повтор помилкових карток
- [x] **8. Режим Match** — сітка плиток, з'єднання пар, таймер, рекорд
- [x] **9. Режим Test** — генерація тесту (вибір, правда/неправда, письмово), оцінка, розбір помилок

## Етап 3 — Покращення

- [x] **10.** Озвучування (Web Speech API), імпорт/експорт (текст/JSON), пошук наборів, темна тема
- [x] **11.** Інтервальне повторення (статистика по кожній картці)

## Етап 4 — Nuxt і бекенд

Обраний шлях: Nuxt + власні server routes + безкоштовна хмарна PostgreSQL.

- [x] **12a. Перенос на Nuxt** — той самий застосунок без бекенду: `app/pages/` замість Vue Router, `@pinia/nuxt`, Tailwind, Vitest + `@nuxt/test-utils`; SPA-режим (`ssr: false`); усі тести проходять; хостинг поки GitHub Pages (`nuxt generate`), на Vercel переїдемо разом із сервером у 12b
- [ ] **12b. Сервер і база** — server routes (`server/api/*`), схема БД (users, study_sets, cards, card_progress), Drizzle ORM; локально SQLite, у продакшені Neon/Supabase Postgres; секрети в `.env`
- [ ] **12c. Акаунти** — вхід (email або OAuth GitHub/Google), сесії, перевірка прав на сервері
- [ ] **12d. Синхронізація** — стори працюють з API (async, оптимістичні оновлення), перенос наявних даних з localStorage в акаунт
